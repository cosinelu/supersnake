# 团队战模式：2v2v2v2v2（设计文档）

> 状态：开发实现中 · 2026-08-27
> 范围：在线联机的「团队对战」新模式。规则/匹配/结算的唯一权威描述。
> 联机底层（协议/同步/房间）见 `docs/architecture/01-online-multiplayer.md`，本模式只描述**团队维度的差异**与新增字段。
> 所有数值真源在 `js/config.js` 的 `TEAM` 段与 `server/config.js` 的团队参数。

---

## 1. 一句话规则

5 支队伍、每队 2 人，共 10 条蛇同场竞技。**同队两人互不伤害**——撞到队友身体、头对头都不会死，还能并肩吃砖块；但**碰到任何非本队蛇的身体立即死亡**（含头对头）。某队两人都阵亡即淘汰该队；场上只剩 1 支队伍时它获胜；若 5 分钟仍有 ≥2 队存活，按**队伍总得分**排名定胜负。

进入该模式是「开房间界面」：若只有你一人点开始，系统会先给你匹配一名队友，再去匹配其它队伍。

## 2. 编制（Roster）

| 项 | 值 | 说明 |
|---|---|---|
| 队伍数 `TEAM_TEAMS` | 5 | 配置项（`server.config.TEAM_TEAMS`） |
| 每队人数 `TEAM_SIZE` | 2 | 配置项（`server.config.TEAM_SIZE`） |
| 总槽位 | 10 | 5 × 2，必须凑满 |
| 真人下限 `TEAM_MIN_HUMANS` | 1 | 超时后至少 1 个真人即可开局（其余 AI 补位） |
| 匹配超时 `TEAM_MATCH_TIMEOUT_MS` | 20000 | 超时后按现有真人 + AI 补满 10 槽开局 |

**槽位填充规则（服务端匹配器负责）：**
1. 带相同 `teamCode`（好友房号）的真人 → 编入同一队（最多 2 人）。
2. 无 `teamCode` 的 solo 真人 → 两两配对成队；落单的 solo 真人 → 与 1 名 AI 编为队友。
3. 以上组成的「人类队」不足 5 队时，用纯 AI 队补齐到 5 队。
4. 每队 2 个槽位：有真人则真人占该槽，空槽由 AI 补位（即单人开局 = 本人 + 1 AI 队友 + 4 个纯 AI 队）。
5. 超时触发与「人数未满」触发都走同一套填充逻辑，保证无论几人都能开局。

## 3. 碰撞与免疫（核心差异）

复用 `js/multiplayer.js` 的 `collide()`，仅新增「队伍维度」分支：

| 碰撞类型 | FFA（原有） | 团队模式 |
|---|---|---|
| 撞墙 / 边界 | 立即死亡 | **立即死亡（不变）** |
| 头 → 自己身体 | 不致死（自吃重组） | 不致死（不变） |
| 头 → 同队身体 | （无队伍概念） | **免死**：不写死亡、不计咬断 |
| 头 → 同队头 | （无队伍概念） | **免死**：双方都存活，可反弹/穿过 |
| 头 → 异队身体 | 撞者死、被撞者记 1 击杀 + 咬断 | **撞者死、被撞者记 1 击杀 + 咬断（跨队）** |
| 头 → 异队头 | 双方死 | **双方死（不变）** |

要点：
- **队伍免疫只发生在「同队」之间**；一切「异队 / 墙 / 边界 / 自身」照旧。
- **咬断（bite-off）只在异队之间发生**：同队头撞身体不触发咬断，不移除身体节。
- 同队两人可以各自吃场上砖块（吃色是各自独立的动作，本就无需特殊处理）；不新增「共享身体」机制。

## 4. 计分与胜负

### 4.1 个人计分（与 FFA 一致）
每条蛇的 `survivalScore`（1 分/秒）+ `elimScore`（击杀/咬断）+ `mpBonusScore`（道具/彩色星）照旧累加。

### 4.2 队伍计分
```
teamScore(teamId) = Σ 该队所有成员（含已阵亡）的 (survivalScore + elimScore + mpBonusScore)
```
阵亡成员保留其生前累计分，计入队伍总分。

### 4.3 胜负判定（淘汰制 + 超时补分）
1. **淘汰**：某队两名成员全部阵亡 → 该队淘汰。
2. **即时胜**：当存活队伍数 ≤ 1 → 仅存的队伍直接获胜。
3. **超时**：对局达 `MATCH_MAX_MS`（5 分钟）且仍有 ≥ 2 队存活 → 按 `teamScore` 排名，分数最高队获胜；同分时并列。
4. 个人结算：本人死亡但队友仍存活 → 收到 `YOU_DIED` 事件进入**观战**（相机跟随存活队友）；整队淘汰 → 收到 `OVER(DEAD)`；本队获胜 → `OVER(WIN)`；本队未夺冠但到超时 → `OVER(LOSE)`。

## 5. 匹配流程（开房间 → 匹配队友 → 匹配其他队伍）

```
主菜单「在线团队赛」按钮
  → 进入 team_lobby（开房间界面）：显示昵称、好友房号(teamCode)、「邀请好友」/「开始匹配」/「返回」
  → 好友开黑（邀请制，见 §5.1）：点「邀请好友」自动生成房号并复制邀请链接
      → 微信粘贴发给好友 → 好友点开链接直达大厅、房号已填 → 各自点开始 → 编入同队
  → 点开始：
      单人：发 join{mode:'team', teamCode:null}
            → 匹配器先给你配一名队友（另一 solo 真人，或 AI）
            → 再凑满其它 4 队（真人 + AI 补位）
      好友开黑：两人持同一 teamCode 发 join{mode:'team', teamCode:'xxxx'}
            → 两人编入同队，再去匹配其它队伍
  → matched（含 3s 倒计时）→ start
  → 对局进行（见 §3/§4）
  → over（含队伍排行 teams[]）→ 结算页 → 返回
```

大厅界面与匹配中提示均由 `js/renderer.js` 在 canvas 上绘制（`drawMatching` 扩出团队大厅态 `team_lobby`）；取消匹配走既有 `CANCEL` 通道。

### 5.1 邀请好友（微信分享）

- **目标形态是「微信邀请好友」而非手输房号**。H5 阶段的落地形态 = **邀请链接**：
  点「邀请好友」→ 前端自动生成 4 位房号（`u.makeTeamCode`，去掉 0/O/1/I/L 易混淆字符）并复制
  `<origin><path>?team=CODE` 到剪贴板 → 粘贴到微信会话发给好友 → 好友点开链接**直接进入团队大厅**
  且房号已自动填好 → 双方各自点「开始匹配」即编同队。
- 手动输入房号**保留**：测试阶段直接口头报号也能组队；也是剪贴板不可用（权限拒绝/非安全上下文）时的兜底。
- 邀请链接解析是纯函数 `u.parseTeamInvite(search)`（DOM-free，可单测）；clipboard 写入只在 `main.js`
  （DOM 层）执行——逻辑层只置 `inviteRequested` 标志位，保持 `js/` 逻辑模块可在 Node 直接加载的红线。
- **后续真·微信分享卡片**（标题+缩略图卡片、`wx.updateAppMessageShareData` / 小游戏 `wx.shareAppMessage`）
  依赖微信 JSSDK 与认证主体/域名，或迁入小游戏壳，留待分发形态确定后接入；协议与房号机制不变，
  只是把「复制链接」换成「调起微信分享面板」。
- 好友房号只在**组队**维度生效：带相同 code 的真人编同队（每 code 最多 2 人，第 3 人降级为 solo，见 §2）。
  它不是独立房间——其它 4 支队伍仍从公共队列匹配/AI 补位。

> **已知行为（贪心成局）**：`_buildTeams` 对落单真人直接编成 1 人队，因此「5 队」在第 **9** 个真人时即可凑齐
> （4 对 + 1 落单），房间会在 9 真人 + 1 AI 时立即成局，第 10 人进入下一局的队列。
> 推论：纯队列匹配**不会出现 10 真人 0 AI 的房间**；两个填同一 teamCode 的好友若恰好是第 9/10 人，
> 可能被拆到两局（先来者配 AI 开局，后来者等下一局）。如需「满 10 真人才开局」需改 `_buildTeams`
> 的落单处理策略（留待后续版本拍板，当前保持贪心）。

## 6. 协议新增字段（两端共享 `js/net/protocol.js`）

| 位置 | 字段 | 说明 |
|---|---|---|
| C2S `join` | `mode: 'ffa'\|'team'` | 区分自由混战与团队战（缺省 `ffa` 保持向后兼容） |
| C2S `join` | `teamCode: string\|null` | 好友房号；solo 为 null |
| S2C `matched` | `mode` | 回显模式 |
| S2C `matched` | `teams: [[{id,name,isHuman}] …]` | **二维数组** `teams[teamId][slot]`（5 队 × 2 槽），供客户端着色/标签 |
| S2C `matched` | `myTeam: int` | 本人所属 teamId |
| 蛇快照 `serSnake/deSnake` | `tm: int` | teamId（-1 = 无队伍，FFA 不影响） |
| S2C `event` | `kind: 'YOU_DIED'` | 本人死而队友活 → 客户端转观战 |
| S2C `over` | `reason` 增加 `LOSE` | 团队未夺冠（超时/被淘汰） |
| S2C `over` | `ranks[].team: int` | 每条蛇附带队伍号 |
| S2C `over` | `teams: [{id, score, aliveCount, rank, members:[...]}]` | 队伍总排行 |

FFA 模式行为完全不变：`mode` 缺省为 `ffa`、`teamCode` 忽略、`tm` 恒 `-1`、`teams/myTeam` 省略、`over` 不带 `teams`。

## 7. 客户端观战与展示

- **观战**：收到 `YOU_DIED` 后 `onlineMatch` 将自身状态置为「已阵亡观战」，相机改跟随存活队友（`game.updateCamera` 在本人非存活时锁定队友 entry）。
- **名牌着色**：`drawNameLabels` 按 `teamId` 取 `teamColor(t)` 上色；队友名字后缀「(队友)」。
- **队伍配色环**：`drawSnakeBody` 在蛇头/身体描边加一圈队伍色环，便于区分敌我。
- **结算页**：`drawMultiResult` 增加「队伍胜负」标题（胜/负/淘汰）+ 队伍排行榜（每队总分、存活人数、成员昵称）。

配色：`js/config.js` 新增 `TEAM_COLORS`（5 队蜡笔配色）与辅助 `teamColor(t)`。

## 8. 与现有规则的边界

- 道具、流星、消除、连锁、连击、彩色星、尾巴节、自吃重组：**全部沿用 FFA / AI 对战既有规则**，团队模式仅在「碰撞免疫」「编制」「胜负结算」「观战」四处有差异。
- 服务器权威、30Hz 模拟、15/30Hz 快照、预测/插值、掉线判负：**全部沿用**，团队模式只是 `room`/`matchmaker` 多接一个 `mode` 分支。
- 掉线：真人掉线 → 该蛇死亡（尸体掉色块）；若该队仍有另一名真人存活，则队友继续、掉线者视为阵亡；若该队两人都掉线/死亡 → 该队淘汰。掉线**不补真人**。
- 本地 AI 对战（单机 `multi` 模式）**不受影响**，仍是无队伍 FFA。团队模式是纯联机体验。

## 9. 测试覆盖（见 `test/net/team.test.js`）

1. **碰撞免疫**：同队 head→body / head→head 后双方均存活、无咬断事件；异队 head→body 撞者死、被撞者 +1 击杀 + 咬断。
2. **匹配分组**：solo 两人 → 编入同队；带相同 teamCode 两人 → 同队；不足 5 队时 AI 补满 10 槽；单人 → 本人 + 1 AI 队友 + 4 AI 队。
3. **队伍胜负**：构造一队两人全灭 → 该队淘汰（aliveTeamCount 减少）；仅剩 1 队 → 该队 `WIN`；超时 → 按 teamScore 排名且 `teams` 字段正确。
4. **无回归**：FFA 在线模式行为不变（同文件/同链路断言）。
